# Backend implementation taskbook v2

v2 by Claude on top of Codex v1. All v1 IDs are kept. New leaves: B1.1.5, B1.1.6, B1.3.5, B3.1.5, B3.3.5, B5.2.6. Baseline code anchors for every leaf are in [anchors-v2.md](anchors-v2.md). Leaves marked **Wave 0** need no media contract and can ship before P2 is complete (see [plan-v2.md](plan-v2.md#wave-schedule)).

Planning baseline: `13e73de53f02248feede47e1eced6ac2086e38dd`. Unless fully qualified, Rust paths below are relative to `backend/src/`. Named new modules/types below are proposals, not existing APIs. Use additive SQL in `backend/src/db.rs::run_migrations`; there is no migration directory at this baseline. Add Rust unit/integration tests in colocated `#[cfg(test)]` modules, using `#[tokio::test]`, temporary SQLite databases and `tempfile` where useful. Run focused tests per leaf and the backend test/lint suite at each PR boundary. Fixture subprocesses, clocks and transport adapters must test failure behavior without requiring production services.

One backend integrator owns wiring in `main.rs`, `db.rs`, `handlers/api.rs` and `stream_bridge.rs`. Domain owners may develop proposed modules in parallel against agreed contracts; they must not edit these shared files concurrently. Every leaf includes implementation and its meaningful verification. A checked leaf requires evidence, not merely merged code.

## B1 — Authorize and identify every producer session

Owner: backend session engineer. Existing files: `handlers/stream_ws.rs`, `stream_bridge.rs`, `handlers/api.rs`, `scheduler.rs`, `main.rs`; proposed `broadcast.rs`. Coding dependencies: B1.1 and B1.3.5 need only the P2.1.1 authorization matrix, which does not wait for the O3 media spike; B1.2–B1.3 need the P2.1.1 identity types. B1 can start before B2, but B2 wiring follows it. **Wave 0:** B1.1.1–B1.1.3, B1.1.5, B1.1.6 and B1.3.5 close live security and stream-corruption holes at baseline and ship through the O1.2.5 interim deploy path. Rollout dependencies: compatible admin clients and staging rehearsal/live tests. PR boundary: B1.1 authorization; B1.2–B1.3 identity and cleanup. Rollback: retain additive fields, use a known compatible image; never restore the unauthorized force/show behavior as a convenience rollback.

### B1.1 — Define authorization independently of show editing

- [ ] **B1.1.1** Add proposed `authorize_broadcast(user, optional_show_id)` using actual roles, direct host assignment and `EXISTS` across every linked artist and show assignment. Require a referenced show to exist; preserve authenticated unscheduled broadcasting with station identity. Verify direct host, admin/superadmin, multiple artist profiles, unrelated account, creator-only and missing-show cases against SQLite.
- [ ] **B1.1.2** Call the helper in `stream_ws_handler` before public producer setup and in manual prerecorded admission; keep trusted scheduled admission explicit and scoped to the confirmed scheduled show. Do not reuse `require_show_editor` as broadcast permission. Verify browser/prerecorded agreement and that a forged show ID never reaches public metadata or recording setup.
- [ ] **B1.1.3** Enforce takeover separately: current stream owner or admin/superadmin only. Recheck ownership under the final session/admission lock rather than trusting the pre-upgrade check. Verify two concurrent starts, unrelated `force=true`, owner reconnect and administrator replacement.
- [ ] **B1.1.4** Separate rehearsal identity from public broadcast identity, including when `show_id` is supplied. Preserve private preview and prevent rehearsal from producing public live metadata or automatic public capture. Verify rehearsal→live and failed transition leave the correct owner/source identity.
- [ ] **B1.1.5** **Wave 0.** Restrict `POST /api/stream/stop` (`handlers/stream_ws.rs::stream_stop`, login-only at baseline) to the current stream owner or admin/superadmin, using the same helper as B1.1.3. Keep the host's own stop working from FlowOnAir/FlowStreaming. Verify guest, unrelated host, owner and admin requests, and that a rejected stop neither kills ffmpeg nor starts finalization.
- [ ] **B1.1.6** **Wave 0.** Stop scheduled and manual prerecorded starts from silently replacing an active producer: `stream_bridge.rs::start_prerecorded_stream` calls `stop_stream` on any active stream at baseline. Refuse the start while another producer is active, record a missed/blocked outcome for that show and send one alert; B2.2.4 later makes this a persisted outcome. Verify a live host keeps streaming when a prerecorded start time passes, and the scheduler does not retry that show late.

### B1.2 — Carry one identity through the producer lifecycle

- [ ] **B1.2.1** Add proposed `BroadcastIdentity` with random broadcast UUID, runtime generation, owner ID, optional authorized show ID, source kind and actual start time; persist a process-unique namespace/UUID so restart cannot alias an old session. Verify generated identities differ across reconstructed application state and nullable show IDs serialize correctly.
- [ ] **B1.2.2** Pass identity through `StreamState::start_stream`, `start_prerecorded_stream`, recorder attachment and output descriptors. Construct it once at successful admission, not from scheduled wall time or display title. Verify a show-title change leaves session identity intact and a new producer receives a new identity.
- [ ] **B1.2.3** Make start completion conditional on its generation; unregister failed/in-flight starts and release child processes when startup, WS upgrade or cancellation fails. Verify failure after reservation, after child spawn and before first audio cannot leave a phantom active session.
- [ ] **B1.2.4** Give browser reconnect/grace-finalization an explicit recording/session token in addition to show ID. Preserve a legitimate reconnect while preventing another session for the same show from cancelling or finalizing its replacement. Verify delayed reconnect callbacks against two successive sessions for one show.

### B1.3 — Make every exit safe against replacement

- [ ] **B1.3.1** Replace unconditional state clearing in browser disconnect, explicit stop, prerecorded natural completion and prerecorded monitor-error paths with generation-matched completion. Verify old child exit and old WS close cannot stop a newer producer.
- [ ] **B1.3.2** Apply the same ownership check to delayed recorder finalizers and stop handlers; detach session resources before awaiting slow cleanup and document lock order. Verify concurrent stop/finalize/reconnect has one finalization and no lock deadlock.
- [ ] **B1.3.3** Preserve the bounded nonblocking recording tee: recording failure marks the archive incomplete while producer audio continues. Verify full recorder queue, failed disk write and dead recorder child do not clear the broadcast identity or stall live chunks.
- [ ] **B1.3.4** Add one lifecycle regression covering manual and scheduled prerecorded admission, rehearsal→live, forced authorized replacement and late cleanup. Verify both producer ownership and emitted identity events, rather than only the public `active` boolean.
- [ ] **B1.3.5** **Wave 0.** Bind each WebSocket's audio writes to the session it started: at baseline a forced takeover replaces `ffmpeg_stdin` in shared state while the old socket's loop keeps calling `write_chunk`, so two WebM streams interleave into the new ffmpeg, and the old socket's exit then calls `stop_stream` on the new session. Carry a session token (the B1.2 generation once it exists) into `write_chunk`/`stop_stream`, reject writes and stops from a superseded token, and send the old socket a `replaced` close message before dropping it. Verify with two concurrent sockets and a fake ffmpeg sink that the new sink receives only the new socket's bytes and survives the old socket's close.

## B2 — Serialize maintenance with producer and capture admission

Owner: backend maintenance engineer, integrated by the shared-file owner. Existing files: `db.rs`, `main.rs`, `handlers/stream_ws.rs`, `handlers/recording.rs`, `handlers/api.rs`, `scheduler.rs`; proposed `maintenance.rs` and `handlers/maintenance.rs`. Coding dependencies: B1 identity and the host-executor protocol frozen in P2; host scripting can proceed against fixtures. Rollout dependencies: split automatic deployment first; bootstrap this API in a controlled legacy maintenance window. Initial readiness waits for all finalization; resumable archival exemption needs B3 evidence. Continuous MP3 readiness needs qualified fallback and MP3; the final HLS-enabled profile additionally requires HLS. Readiness cannot silently downgrade an activated capability. PR boundary: schema/state machine; admission/schedule integration; authenticated executor API. Rollback: leave the gate closed, fence the executor and recover deliberately; do not run an old gate-unaware image under normal automated replacement.

### B2.1 — Persist the gate and atomic admission decisions

- [ ] **B2.1.1** Add a maintenance operation record with operation ID, owner, reason, reserved UTC interval, state and transition audit. Implement open→draining→ready→replacing→verifying→open with operation-ID compare-and-set. Verify illegal transitions, stale IDs and restart during each closed state remain closed.
- [ ] **B2.1.2** Add proposed `AdmissionPermit` covering producer, rehearsal, capture and in-flight startup registrations. Serialize permit creation and open→draining under one documented database/application lock order; never hold a DB transaction across subprocess/network waits. Verify a barrier-controlled start/acquire race admits exactly one side.
- [ ] **B2.1.3** Route WS starts/reconnects that create work, manual/scheduled prerecorded starts, explicit `start_recording`, automatic `ensure_recording_started` and rehearsal→live transitions through admission. Allow existing registered work to finish. Verify every entry route is rejected while draining without creating children, files or claims.
- [ ] **B2.1.4** Track finalization and pending start completion separately from public `active`; compute readiness from registered resources, not `/api/stream/status`. Verify inactive public rehearsal, detached finalization and startup-in-progress each block replacement.

### B2.2 — Reserve the schedule window without missed late playout

- [ ] **B2.2.1** Resolve schedule instants explicitly in Europe/Berlin, rejecting ambiguous/nonexistent local times unless an explicit valid instant resolves them. Use injected monotonic clocks for waits and UTC for reservations. Verify both daylight-saving transitions and wall-clock correction do not duplicate admission.
- [ ] **B2.2.2** Check live and prerecorded starts atomically during gate acquisition for the expected deploy+rollback window plus margin, initially at least 30 minutes. Recheck immediately before replacement and whenever extending the reservation. Verify a show on either reservation boundary and a concurrent schedule insert.
- [ ] **B2.2.3** Guard every schedule mutation capable of adding/moving a start into a reserved interval; return an actionable maintenance conflict with stable error code, reserved interval and explicit retry/recovery guidance for the admin UI. Give rejected producer/capture starts the same structured contract without implying automatic reopening. Resolve affected show instants in the same serialized decision. Verify create, edit, reassignment/template paths where they alter the schedule, and edits outside the interval.
- [ ] **B2.2.4** Persist blocked/missed scheduled-start outcomes and alert once per occurrence; change the existing scheduler's catch-up/retry behavior so maintenance or an unready asset never silently starts that show late. Preserve explicit authorized manual retry as a distinct operator action. Verify maintenance overrun and API restart leave fallback selected with a visible missed start.

### B2.3 — Bind gate transitions to the trusted deployment executor

- [ ] **B2.3.1** Add authenticated, publicly denied executor endpoints for acquire/status/transition/release, using operation IDs and ownership checks at each mutation. Require fresh readiness and schedule evidence before returning replace permission. Verify stale readiness and unauthenticated/public requests fail closed.
- [ ] **B2.3.2** Implement the API side of P2's root-owned host executor contract: lifetime lock, durable operation journal and cgroup fencing of executor/children. Recovery may restore a compatible image without a live API, then reconcile the still-closed gate after API return. Keep the API as the only database writer and never give it the Docker socket. Verify a paused old executor cannot mutate services after recovery and API absence does not require direct host edits to SQLite.
- [ ] **B2.3.3** Keep expired/lost operations closed and alert; only explicit authenticated recovery releases them. Define a logged incident override with operator/reason/expected interruption, separate from normal deployment. Verify deadline passage alone never opens starts and a recovery action records who changed the state.
- [ ] **B2.3.4** Implement readiness phases: legacy bootstrap requires no active/in-flight work, complete finalization and the available legacy health checks; qualified target mode additionally requires healthy local fallback and both outputs. After replacement require schema health and gate ownership; add B3 recording reconciliation and B5 current-output handshake as those features become active. Record the phase explicitly so target deployments cannot downgrade their checks. Verify unavailable API recovery and each phase's missing readiness input block release without requiring not-yet-installed features during bootstrap.
- [ ] **B2.3.5** Implement the startup barrier in `main.rs`: inspect persistent gate and read-only trusted host journal/recovery-mode evidence before accepting producer/capture admission or spawning scheduler and optional background work. An incomplete/corrupt recovery record holds admissions closed; diagnostics and reconciliation remain available. Verify an open DB with a pending incident journal, restart, host reboot and compatible rollback images cannot admit work before reconciliation.

## B3 — Make recording capture, recovery and cleanup durable

Owner: backend recording engineer. Existing files: `recording.rs`, `handlers/recording.rs`, `stream_bridge.rs`, `storage.rs`, `db.rs`, `main.rs`; proposed `recording_manifest.rs`. Coding dependencies: B1 identity; B2 readiness adapter can follow independently. Rollout dependencies: persistent spool/reserve checks, compatible SQLite validation and isolated crash harness. PR boundary: manifests/marker persistence; idempotent archive reconciliation; cleanup/handoff enablement. Rollback: preserve manifests/files and additive rows; disable resumable maintenance handoff before returning to a version that cannot recover it. Never roll back by deleting pending recordings.

### B3.1 — Record recoverable capture state before acknowledging it

- [ ] **B3.1.1** Define versioned `RecordingManifest`: recording UUID, show/version, producer generation, ordered closed segment descriptors, durable markers, state, expected keys/checksums and incomplete reason. Add required additive DB indexes/uniqueness to avoid duplicate versions. Verify migration twice, legacy rows and rejection of corrupt/unsupported manifests without deletion.
- [ ] **B3.1.2** Persist capture start and each marker using atomic publication/durable flush before acknowledging persistence; record closed segments only after files are flushed and final filenames durable. Specify data-file, manifest and parent-directory sync order. Verify restart after each publication step discovers either the prior safe state or the complete new state.
- [ ] **B3.1.3** Preserve markers across restart instead of orphan recovery supplying `[]`; bind marker writes to recording UUID/generation and make retry identity explicit. Verify a delayed marker cannot attach to a replacement recording and acknowledged markers survive a process kill.
- [ ] **B3.1.4** Seal capture by stopping the writer, flushing closed files and marking incomplete tails distinctly; validate/quarantine or repair a tail before recovery. Keep bounded recorder backpressure independent of live ingest. Verify kill mid-segment, flush failure and recorder queue overflow recover only validated material and visibly mark incomplete archives.
- [ ] **B3.1.5** Keep closed segments until the archive built from them is remote-verified and indexed. At baseline `stream_bridge.rs::stop_recording` deletes the `*.segs/` directory right after `concat_segments`, so a bad concat loses the only good copy. Move segment deletion into the B3.2.1 cleanup-eligible transition. Verify a corrupted concat output is detected and rebuilt from the retained segments.

### B3.2 — Reconcile archival idempotently across every crash boundary

- [ ] **B3.2.1** Implement capturing→sealed→upload pending→remote verified→indexed→cleanup eligible transitions in a single proposed reconciliation entry point used by normal finalization and startup recovery. Serialize per recording UUID and reconcile before any cleanup task. Verify simultaneous normal finalization, retry and recovery produce one transition sequence.
- [ ] **B3.2.2** Use deterministic immutable object references and bounded streaming file upload rather than reading full long recordings into memory. Verify expected sizes and content checksums using supported remote verification or read-back; never treat multipart ETag or positive size as sufficient. Verify wrong bytes with the same size do not advance remote-verified state.
- [ ] **B3.2.3** Commit recording/version and marker references only after the required raw audio, marker file and any required derived archive are verified; make DB insertion idempotent by recording identity. Keep raw archival and optional derived/export states distinct. Reconcile upload-success/DB-failure and DB-success/manifest-failure without overwriting another version. Verify injected failure at every boundary yields exactly one correct indexed version after retry.
- [ ] **B3.2.4** Keep SoundCloud/Instagram/Telegram work downstream of durable archive success and outside capture completion. Bound optional retries/timeouts and avoid automatic duplicate publication after ambiguous provider outcomes. Verify provider/R2 failure leaves recoverable recording state and does not block live audio or falsely mark archival success.

### B3.3 — Protect local data and expose safe maintenance handoff

- [ ] **B3.3.1** Replace age-only `cleanup_stale_files` handling of recordings with manifest/DB/verification-aware eligibility; keep unrelated temp cleanup separately scoped. Serialize cleanup with finalization/recovery and reject path traversal/symlink escape. Verify old unverified captures survive disk pressure, while verified indexed artifacts are removable.
- [ ] **B3.3.2** Add authenticated backlog/incomplete status and explicit retry operations, including recording ID, lifecycle state, original failure, last successful step and permitted next action; provide response fixtures to the admin UI owner. Preserve legacy orphan discovery with conservative incomplete labeling and no fabricated marker history. Verify retry twice, unavailable R2 and a malformed legacy directory never lose files.
- [ ] **B3.3.3** Expose a durable handoff result to B2 only after capture is stopped, all closed segment/manifest/directory flushes succeed and restart discovery is proved. Initially block maintenance on finalization; enable pending archival exemption only after crash exercises pass. Verify a merely stopped ffmpeg child or pending fsync cannot satisfy readiness.
- [ ] **B3.3.4** Integrate reserve-aware capture admission and one heavy non-live job permit with operations resource limits; prioritize archive work and keep ingest/capture/continuous encoders outside that permit. Verify rejected new capture explains capacity, active capture remains protected, optional work yields, and no unverified data is deleted to satisfy a quota.
- [ ] **B3.3.5** **Wave 0.** Stop the daily age-only deletion of unuploaded recordings now, before the full B3.3.1 rework. At baseline `main.rs` runs `storage::cleanup_stale_files("./data/recordings-temp", 24h)` daily; `tokio::time::interval` fires its first tick immediately, so it runs at boot concurrently with `recover_orphaned_recordings` and can delete a >24 h orphan before recovery uploads it, and it deletes any recording whose upload kept failing for a day. Interim rule: skip `recording_*` artifacts and `*.segs/` directories unless a matching `recording_versions` row is finalized with a verified remote size; skip the immediate first tick; log what was kept. Verify an old unverified recording survives cleanup, a verified one is removed, and boot ordering cannot delete before recovery ran.
