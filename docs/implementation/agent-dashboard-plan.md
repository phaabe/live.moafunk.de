## Goal

The dashboard answers, in this order:

1. Do I need to act?
2. Which agents exist? What is each one doing, and does one wait for another?
3. Is the loop healthy (ticks succeed, not fail, time out or hang)?
4. How far along is the epic, and how fast?

## Problems today

- "Last exit" shows a raw red `1`. Exit 1 is often a `gh`/`git` failure in the
  runner, not a model failure. Exit codes are never named. Fixed by PR 1.
- The last exit comes from a 128 KiB log tail. No tick history, failure rate,
  durations or tokens. Fixed by PR 1.
- Collected data is not shown: `codex-backoff.json`, `claude-permissions.log`,
  Codex `tokens used`.
- No handoff view and no trends. Wasted space; truncated leaf titles.
- **The agent list is hard-coded** (`AGENTS` in `monitor.py`, `dashboards.py`,
  the Alloy file list, fixed state file names). A third agent is invisible.

## Rules

- **Trust boundary.** Runner logs mix runner output with model output,
  prompts and command output, so a line in them cannot prove who wrote it.
  - Preferred tick data comes from a runner-written events file (PR 3).
    It is trusted for Codex (its sandbox cannot write there). For Claude it is
    best effort too, because write isolation from the model is not proven.
  - Data parsed from the old logs is **best effort**, marked
    `source="log"`, and used only for ticks before the events file exists.
  - Metrics carry only counts, timestamps, numbers, fixed enums, validated
    agent ids and labels, and URLs/titles normalized by the existing
    `action_labels()` / GitHub snapshot. Never exported: `gh`/`git`
    arguments, permission commands or reasons, backoff summaries, model
    summaries, raw log lines.
- Stale data shows grey "unknown", never green or zero. Alerts are gated on
  freshness **and** read health of every source they use.
- Dashboards stay generated by `dashboards.py`; the JSON-up-to-date test stays.
- Dashboards never list agents by hand. Every per-agent panel is built from
  the `agent` label. Agent colors come from the agent's kind.
- The dashboard stays read-only. It never starts, stops or registers an agent.
- The runners' selector input (`next_action.fetch_state()`) and the runner log
  format do not change.
- Daily and hourly values use Europe/Berlin local time, computed in the
  collector (DST days have 23 or 25 hours).

## Agent model

- **Agent** = one runner instance with its own lock, log and schedule. It has
  an id, for example `claude`, `claude-2` or `codex-review`.
- **Kind** = the runner type: `claude` or `codex` (fixed enum in code; a new
  kind is a code change). The kind picks the runner script, the color and the
  features. For example, only `claude` has a permission gate and only `codex`
  reports tokens and backoff.
- Id format: `^(claude|codex)(-[a-z0-9]{1,16})?$`. The kind is the id prefix,
  so the dashboards can color rows by a regex on `agent` with no join.
- **Work attribution stays per kind.** GitHub only knows `Executor: Claude` /
  `Reviewer: Codex`, and both agents use one GitHub account. So epic progress,
  PR flow, merged PRs and handoff are per kind. Runtime data (state, ticks,
  outcomes, backoff, permissions) is per agent.

### Registration

An agent registers by writing one file. The collector finds it on its next
cycle (5 s). There is no network listener: the collector has no open port,
and a file keeps the existing trust model.

Layout for a registered agent: `$EPIC_STATE_DIR/agents/<id>/` holds
`agent.json` plus **the same files as the legacy state dir**
(`<kind>.lock/`, `<kind>.log`, `<kind>-gate.json`, `codex-backoff.json`,
`claude-permissions.log`, later `<kind>-ticks.jsonl`). The runner points
`state_dir` and `EPIC_STATE_DIR` at the folder, so `tick_gate.py`,
`permission_gate.py` and `tick_backoff.py` need no change.

`agent.json` (written by `agents.py register` / `retire`):
`{"v":1,"id","kind","label","interval_seconds","budget_seconds","registered_at","retired_at"}`

- New CLI `scripts/epic/agents.py`:
  - `register --id <id> [--label <text>] [--interval <s>] [--budget <s>]`
    creates the
    directory and writes `agent.json` atomically. It is idempotent: a second
    call keeps `registered_at`.
  - `retire --id <id>` sets `retired_at`. The directory stays for history.
  - `list` prints the registry and the collector's view of each agent.
- Runners read `EPIC_AGENT_ID`:
  - Unset: the legacy paths stay exactly as today (`claude.lock`,
    `claude.log`, `claude-gate.json`, …). The running launchd jobs do not
    change.
  - Set: the runner uses `agents/<id>/` and calls `agents.py register` at
    the start of each tick (after the pause check). The id must start with
    the runner's kind. `EPIC_AGENT_LABEL` and `EPIC_AGENT_INTERVAL_SECONDS`
    are optional; the budget is the runner's lock budget.
  - `.codex/codex-tick.sh` also accepts `EPIC_STATE_DIR` (it was
    hard-coded).
- **Legacy agents.** If `claude.log` or `claude.lock` exists in the state
  dir, the collector adds the implicit agent `claude` with
  `layout="legacy"`. The same applies to `codex`. A registered id `claude`
  and a legacy `claude` at the same time is a conflict: the collector keeps
  the registered one and sets `epic_agent_conflict{agent} 1`.
- Validation in the collector:
  - The id matches the regex, and the directory name equals `id`.
  - The agent directory is a real directory, not a symlink (`lstat`). Every
    file is opened relative to it, so the collector never reads outside the
    state dir.
  - `label`: at most 40 printable characters, no control or markup
    characters. Otherwise the id is shown.
  - `interval_seconds`: 30 to 86 400, default 600.
  - `budget_seconds` (the runner's whole tick budget, the lock `max_age`):
    10 to 86 400, default 3 600. The runner passes its real value. It is
    needed for the `late` rule while no tick runs.
  - At most **12 agents** (not retired) are exported, sorted by
    `registered_at`. More are rejected and counted in
    `epic_agent_registry_rejected{reason}` with reasons `invalid`, `limit`
    and `conflict`. The cap protects the scrape size and the cockpit layout.
- Trust: the Claude model may be able to write the registry (same gap as
  `events_unverified`). A forged registration can add at most a few fake rows
  and cannot make the collector read outside the state dir. This risk is
  accepted for a local read-only dashboard.

### Presence

The collector derives one presence value per agent (fixed enum, severity
order):

| Presence | Rule |
|---|---|
| `running` | the lock owner PID is alive |
| `idle` | no tick runs, and the last tick start is within `2 × interval + budget` |
| `late` | no tick start for longer than `2 × interval + budget_seconds`, loop not paused: the schedule may be broken |
| `new` | registered, but no tick seen yet (becomes `late` after the same limit) |
| `unknown` | the lock or gate could not be read this cycle, or a lock has no owner; never shown as idle or late |
| `retired` | `retired_at` is set |

- `late` is the "is it still alive?" signal. There is no heartbeat besides
  tick starts, so an agent with a long interval turns `late` later.
- Retired agents stay in the cockpit for 24 h (grey, at the bottom; runtime
  cells show "–"). After that, the collector stops exporting their series.
  Their history stays in Prometheus (30 days).
- A pause never makes an agent late (no tick starts on purpose), and no next
  tick is exported. The Paused tile shows the pause.
- Deleting `agents/<id>/` removes the agent and its checkpoint at once.

### Collisions

The selector (`next_action.py --agent <kind>`) knows only kinds. Two running
agents of the same kind can pick the same action. Coordinating them is out of
scope for this plan: it belongs to the epic runner rules. The dashboard makes
it visible:
- `epic_agent_collision{agent, target} 1` when two or more running agents
  have the same current action target.
- The cockpit shows a "Collisions" attention tile.

## Tick model

A tick runs from start to finish of one runner invocation that holds the lock.

- Running now: only `owner.json` + PID liveness (existing `runner_metrics`).
  `max_age` is the whole budget (selector + model + kill grace); exported as
  `epic_tick_budget_seconds`.
- Lock contention happens before the tick starts (`claude-tick.sh:41–79`);
  `tick: locked; …` lines are contender events, not ticks.
- A tick with no finish before the next start is `interrupted`.

Outcome enum, severity order for "worst": ok 1 < blocked 2 < timeout 3 <
killed 4 < interrupted 5 < error 6.

Phase enum (the stage a tick ended in), runner-owned, replaces free-text
reasons: `lock`, `refresh`, `select`, `quota`, `backoff`, `gate`, `model`,
`result`, `verify`, `record`, `unknown`.

### Events file (preferred source, PR 3)

Runners append one JSON line per event to `<kind>-ticks.jsonl` in their
state dir (`agents/<id>/` for registered agents). Each line is one atomic `printf` of
< 4 KiB, so lines never interleave:

```json
{"v":1,"event":"start","tick":"2026-09-28T15:39:39Z","pid":38604}
{"v":1,"event":"finish","tick":"2026-09-28T15:39:39Z","at":"2026-09-28T15:47:10Z","exit":0,"outcome":"ok","phase":"model","action":"review","pr":436,"issue":null,"tokens":89040}
```

- `outcome` and `phase` are set by the script, which knows each path:
  Codex blocked result → `blocked`/`result`; invalid result →
  `error`/`result`; Claude GitHub quota stop → `blocked`/`quota`; selector
  failure → `error`/`select`; `run_bounded` 124 → `timeout`, 129/130/143 →
  `killed`. Written by `scripts/epic/tick_events.py`; the finish event is
  written before the lock is released.
- The finish time is the event's `at`, so event ticks have a real duration.
- Once an agent has events, its log ledger stops counting; history before
  the first event still comes from the log.
- `tokens` (Codex): the last `tokens used` count printed after this tick's
  start offset in its log (numeric only). Best effort; `null` if absent.
- Who can write the file: Codex's sandbox write roots do not include
  `~/.local/state` (seen in the session header). For Claude this is **not**
  proven: `permission_gate.py` only answers prompts; it does not block file
  writes. Remaining risk, accepted for a local read-only dashboard: Claude
  event rows carry `source="events_unverified"`, Codex rows `source="events"`.
  The collector checks what it can check after the fact (the lock files are
  deleted when a tick ends, so no pid check): schema and enums, one finish per
  start, finish after start, start times increase. Invalid lines are counted
  in `epic_tick_events_rejected_total` and ignored.

### Legacy log parser (best effort, PR 1, built)

For history before the events file:

- `tick: started <ISO> repo=…` to `tick: finished exit=N` (exact whole line).
- Exit 0 ok · 124 timeout · 143 killed · 75 blocked **only if** the tick has
  `backoff: model reported blocked: …`, else error · other non-zero error.
- Tokens: `tokens used` then a plain number (with or without commas).
- End time: the legacy finish line has none. If the collector reads the
  finish in a live increment (after the baseline), end = read time (up to 5 s
  late). For history before the baseline, end and duration are unknown
  (`-1`, shown as "–"). Start times always come from the start line.
- Phase: `select` if the tick has `CalledProcessError: Command '['gh'`, else
  `unknown`.
- Tests include exact, unindented forged markers inside model output to
  document that the legacy path can be fooled. That is why it is labeled best
  effort and replaced by the events file.

### PR 2 — Agent registry and presence (new in v4)

Collector:
- New `scripts/epic/agents.py`: registry model, validation, `register`,
  `retire`, `list` CLI, legacy discovery. One function
  `discover(state_dir, now) -> list[Agent]` is the only place that knows the

  registered and retired times.
- `monitor.py`: `AGENTS` is removed. `runner_metrics` and `make_ledgers` loop
  over `discover()`. Ledgers are created and dropped as agents appear and
  disappear; checkpoints are keyed by id.
- New metrics:

| Metric | Labels | Meaning |
|---|---|---|
| `epic_agent_info` | agent, kind, label, layout (`legacy`/`registered`) | value = registered_at (legacy: first seen) |
| `epic_agent_budget_seconds` | agent | registered budget (running tick: lock `max_age` wins) |
| `epic_agent_presence` | agent | severity: running 1, idle 2, new 3, late 4, unknown 5, retired 0 |
| `epic_agent_presence_info` | agent, presence | 1; for tables |
| `epic_agent_interval_seconds` | agent | expected tick interval |
| `epic_agent_last_start_timestamp_seconds` | agent | last tick start seen (ledger or lock) |
| `epic_agent_next_tick_seconds` | agent | last start + interval − now; negative = due; no series while running, paused or retired |
| `epic_agent_row_info` | agent, action_text, outcome_text | 1; cockpit text cells (see "Design v2 decisions") |
| `epic_agent_order` | agent | sort key for the cockpit table: presence, then kind, then id |
| `epic_agent_recent` | agent, slot (`01`–`20`, `20` = newest) | severity of the last 20 finished ticks; no series for empty slots |
| `epic_agent_collision` | agent, target | 1 when two running agents share a target |
| `epic_agent_conflict` | agent | 1 when a legacy and a registered agent share an id |
| `epic_agents_registered` | presence | count per presence |
| `epic_agent_registry_rejected` | reason | rejected registrations in the last cycle |

- `epic_agent_recent` exists because a Grafana table cannot draw a strip of
  20 colored cells from `epic_tick_info` (see PR 5).

Runners:
- `claude-tick.sh`, `codex-tick.sh`: `EPIC_AGENT_ID` as described in
  "Registration". The helpers follow `EPIC_STATE_DIR`, so the gate,
  backoff and permission files land in the agent's folder.

Alloy:
- Alloy follows links when it opens a file, and agents can write their
  folders, so Alloy never globs them. The collector writes
  `runtime/alloy/targets.json` each cycle: the log of every known agent that
  is a regular file (no link), with its `agent` label. Alloy reads it with
  `discovery.file` (every 10 s). A new agent's log appears without a restart.
- Remaining gap: a log swapped for a link after the check is followed when
  Alloy reopens it. Impact is small: the container sees only the state dir
  and its own files, and the model can already print anything it can read
  into its log.

Collector reads:
- Every agent file (lock, gate, log, ledger) is opened relative to the state
  dir, one folder at a time with `O_NOFOLLOW`, and must be a regular file.
- A malformed `agent.json` (huge numbers, deep nesting, bad Unicode) rejects
  only that agent; a bad label falls back to the id.
- Every checkpoint without a current agent is deleted, also after a
  collector restart, so a restored log is never counted again. A returning
  agent starts with fresh counters.
- One unreadable or swapped agent folder rejects only that agent.
- Metric samples are grouped by family, as the text format requires.

Scrape size:
- Per agent at most about 250 samples (168 hour cells, 20 ticks, 20 recent
  slots, the rest). 12 agents add about 3 000 to the 5 900 GitHub samples.
- The max fixture test is extended to 12 agents with full ledgers (one
  running): 8 806 samples measured. The guard is 10 000 samples.
- Series churn over 30 days: about 80 `epic_tick_info` series per agent per
  day, so up to about 30 k for 12 busy agents. Acceptable for local
  Prometheus.

Tests (`test_agents.py`, `test_monitor.py`, runner tests): register is
idempotent; retire; invalid id, kind mismatch, directory name mismatch,
symlinked directory, overlong or control-character label, interval out of
range; the 13th agent is rejected with `limit`; legacy discovery with and
without a registered agent of the same id (`conflict`); presence for each
state incl. the `late` edge and retired-after-24-h; an agent appearing and
disappearing between cycles (ledger created, then dropped, no crash);
collision; the recent strip; runners with and without `EPIC_AGENT_ID` write
to the right paths; the Alloy target list; no-follow reads; metric families
contiguous; a returning agent; collisions from current actions only;
retired cap; custom and unset `EPIC_STATE_DIR` in both runners.

### PR 3 — Runner events file, backoff, permission gate

Same as v3.2 PR 2, with per-agent paths:

- Runners write start/finish events (format above) to the agent's events
  file. The existing log lines stay unchanged.
- `.codex/tick_backoff.py`: new entries store `until = at + ttl`; `check`
  uses `until` when present, else `at + --ttl`.
- Collector prefers events for ticks after the first event; legacy parser for
  older ones. Tick `source` label: `events`, `events_unverified` or `log`.
- `epic_backoff_info{agent, target, head, estimated, current_head}`: active
  entries only; value = `until`. `estimated="true"` for old entries without
  `until` (runner default 900 s). `current_head` = `true`/`false`/`unknown`
  from the PR heads of the last successful GitHub poll (held in memory; the
  runner loop reads them). Keys are unique per `(target, head)`.
- `epic_permission_decisions_total{agent, decision}` counter from an
  incremental read of the agent's permissions log (same checkpoint rules).
  Only for kinds with a permission gate.
- Alloy: permissions logs as a second stream per agent, listed by the
  collector with `stream="permissions"`. `loki.process` with a
  `stage.match` on that stream: `stage.regex` `^(?P<ts>\S+) (?P<decision>allow|deny) ` →
  `stage.timestamp` (RFC3339) → `stage.labels` (`decision`) → `stage.drop`
  `older_than = "167h"` (Loki rejects lines older than one week).
  Runner-log queries add `stream!="permissions"`.

Tests: events written on every runner exit path (ok, blocked, invalid
result, selector failure, timeout, kill); backoff `until` used by `check`;
event/legacy merge; event validation (orphan finish, finish before start,
bad enum, out-of-order start), also after the lock is gone and after a
collector restart; backoff estimated/current_head/dedupe/expiry; permission
counter; two agents of the same kind write to separate files.

### PR 4 — Monitor-only GitHub delivery and handoff data

Same as v3.2 PR 3. Handoff is per kind, because GitHub knows only kinds:

- New `monitor.fetch_delivery()`, own snapshot and
  `epic_delivery_snapshot_timestamp_seconds`. Open PRs: `createdAt`. PRs
  merged in the last 14 days: `createdAt`, `mergedAt`, full comments via the
  paginated REST call with the completeness check of `fetch_state()`. Merged
  PRs are revalidated every 30 min. Incomplete history →
  `epic_delivery_complete 0`. Failure keeps the last snapshot.
- Handoff waits (`runtime/handoff.json`): a PR waits for review when
  `decide(reviewer kind)` includes `review` for it. `first_seen[(PR, head)]`
  is set on the first successful observation and removed when a successful
  observation shows the PR not waiting. A failed observation changes
  nothing.
  - `epic_handoff_wait_seconds{waiter_kind, waits_for_kind, target}`.
- `epic_handoff_stalled` = 1 when both kinds have an observed wait > 30 min,
  the loop is not paused, **no agent of either kind** is `running`, `new` or
  `unknown`, and all sources are fresh. Called "suspected stalled handoff".
- `epic_agents_registered_kind{kind}` (agents not retired). The handoff
  panel turns amber when a kind's PRs wait and no agent of the reviewer kind
  is registered.
- Delivery metrics use `kind`, not `agent`: `epic_area_leaves{area, kind,
  state}`, `epic_merged_prs_day{kind, day}`, `epic_pr_flow_info{target,
  executor, reviewer, opened, state}`, `epic_review_rounds_median`,
  `epic_time_to_merge_median_seconds`.
- Tests as in v3.2, plus the stalled rule with two agents of one kind (one
  running blocks "stalled").

### PR 5 — Dashboards and alerts

Three dashboards. Grid, colors and thresholds come from design v2 (appendix).

- `epic-agents` **Cockpit** (keeps the home URL).
- `epic-agent` **Agent detail**, variables `agent` (query
  `label_values(epic_agent_info, agent)`, so new agents appear on their own)
  and `search`. `epic-agent-claude` / `epic-agent-codex` become a text panel
  linking to `epic-agent?var-agent=…`.
- `epic-delivery` **Delivery**, per kind.

Cockpit agent table (the main change in v4; column spec in the appendix):
- One Table panel, one 36 px row per agent, 8 rows visible, 9–12 scroll.
  Instant queries with `format=table`: `epic_agent_info`,
  `epic_agent_presence_info`, `epic_agent_order`, `epic_agent_row_info`,
  `epic_current_action_info` (task path), elapsed / budget,
  `epic_tick_last_info`, `epic_tick_consecutive_failures`,
  `epic_agent_recent`, `epic_agent_next_tick_seconds`, backoff count,
  denials 1 h.
- Transformations: "Grouping to matrix" on the `epic_agent_recent` query only
  (row `agent`, column `slot`) → "Join by field" `agent` (outer) → "Organize
  fields" (hide the sort key and helper fields) → "Sort by"
  `epic_agent_order`.
- Cells: presence, outcome, failures and collision as colored background with
  value mappings; tick elapsed as a basic gauge cell (thresholds 0.7, 0.9);
  20 slot columns 8 px wide (override regex `^\d\d$`), text hidden, header
  " "; the kind column 6 px with text hidden; the agent cell links to
  `/d/epic-agent?var-agent=${__value.raw}`; action and task link to GitHub.
- Retired rows: runtime fields have no value, so cells show "–"; presence is
  grey text. Stale data: presence and last outcome map "no value" to "data
  stale".
- **Spike first:** confirm in Grafana 13 that a per-query transformation
  filter plus the outer join keeps one row per agent when some queries have
  no series for an agent. Fallback for the strip: one "Last 20" cell with
  counts ("17 ok · 2 err · 1 blk"), colored by the worst outcome.

Other panel semantics:
- **Tick outcomes · 24 h**: state timeline, one row per agent, value =
  `epic_tick_last_outcome` (held). Retired agents are hidden. The activity
  row moves to the agent page.
- **Attention tiles** (8, from the appendix): Needs Anton, Paused, Agents
  (running / registered), Agents failing, Agents late, Collisions, PRs
  waiting > 30 min, Data freshness. The backoff and denials tiles move into
  table columns.
- **Tick history**, **Outcome per hour · 7 days**, **Errors only**,
  **Permission gate**, **Last 10 denials**, **Tick elapsed**, **Burn-up** as
  in v3.2, with `agent="$agent"`. Panels for a feature the agent's kind does
  not have show "not reported by this runner" in grey.
- Guards: local panels `LOCAL`, GitHub panels `GITHUB`, delivery panels
  `DELIVERY` (`time() - epic_delivery_snapshot_timestamp_seconds < 600`).
- "Needs Anton" = needs-anton labels + pause (amber only) + stalled
  handoff + any agent failing ≥ 3 in a row + any late agent + any collision +
  a spike (≥ 5 denials in 1 h, or ≥ 3 items in backoff, on one agent) + a PR
  waiting > 60 min.

Alerts (`alerts.yml`), all per `agent` label so new agents are covered:
- `AgentFailingRepeatedly`: `epic_tick_consecutive_failures >= 3`, local
  fresh, `epic_runner_read_success == 1`; for 1 m.
- `AgentLate`: `epic_agent_presence == 4` and local fresh; for 5 m.
- `AgentCollision`: `epic_agent_collision == 1`; for 1 m.
- `AgentHandoffStalled`: as in v3.2.
- Existing stale-source alerts stay. `promtool test rules` for firing,
  stale, missing, read failure, recovery and a new agent appearing.

Tests (`test_dashboards.py`): no dashboard contains a literal agent id except
the two redirect pages; uids; transformations match used labels; JSON up to
date. Manual: compare with design v2 at 1600 and 1280 px; reproduce the 10
design scenarios (normal, single, busy, full, late, failing, collision,
retired, paused, stale) with fixture state dirs.

## Out of scope

- Starting, stopping or scheduling agents from the dashboard or collector.
- Coordinating several agents of one kind in the selector (the dashboard only
  shows collisions).
- Per-agent work attribution on GitHub (needs an agent id in the PR text).

## Design v2 decisions

Design v2 (Claude Design project "Dashboard Redesign", file
`Dashboard Redesign.dc.html`, scenarios in `Cockpit.dc.html`) is the layout
source. Its "Data" column uses example metric names; this plan's metrics
replace them. Where the design and the plan differ:

| Design v2 | Plan | Why |
|---|---|---|
| Text cells with ages: "error 1 · 4m · gh pr list", "in 2m", "due 12 min" | `outcome_text` = "error 1 · select" (outcome, exit, phase; stable per tick). Age is its own narrow "Ago" column from `epic_tick_last_info` (unit "from now"). "Next tick" is the number `epic_agent_next_tick_seconds` (negative = due, red) | an age in a label makes a new series every minute; command text never enters metrics |
| `action_text` with "last: " and "collision · " prefixes | same, built by the collector from `action_labels()` + collision | stable per tick |
| "Next tick: in progress / paused / first in 4m" | running, paused, new → no value, cell "–"; running shows in Presence and Tick elapsed; pause in the Paused tile | no text that changes with time |
| Exit-code value mappings, interrupted = 130 | mappings on the outcome severity (`epic_outcome_severity`); interrupted has no exit code | the ledger knows the outcome, not always an exit code |
| Tick history from Loki JSON events; hourly worst from 7 offset queries; median from a histogram | `epic_tick_info`, `epic_tick_hour_worst`, `epic_tick_duration_today_seconds` | built in PR 1; Codex review showed the PromQL hourly approach is wrong |
| Items-in-backoff and denials tiles dropped; spikes still raise "Needs Anton" | spike = any agent with ≥ 5 denials in 1 h or ≥ 3 items in backoff | the design gives no number |
| Handoff amber when no agent of the reviewer kind is registered | added to PR 4 (`epic_agents_registered_kind{kind}`) | new rule |
| Agent picker: registered ids plus ids retired in the last 24 h | same | |
| Epic link in the chrome (mock number) | link to https://github.com/phaabe/live.moafunk.de/issues/312 | real epic |
